# zohelo-bi architecture

```
zohelo-data (GitHub Actions)                 zohelo-bi (Cloudflare)
  Landing → Bronze → Silver → Gold   ──►  R2 Data Catalog (Iceberg) ◄── R2 SQL
             └──► 06_published/v1 (catalogue, latest values)                ▲
                                                                            │
  browser ── Access sign-in ── Pages: portal (static) + /api (Functions) ───┘
```

- **Portal** (`apps/portal/src`): the design template. `tpl/TplApp.tsx` is the shell and the route table
  (`tpl/routes.ts`); every page is its own chunk, loaded when its route opens. Old-portal addresses are rewritten
  before the first render (`tpl/legacy.ts`).
- **Data** (`apps/portal/src/data`): one `DataProvider` interface (`catalog`, `series`, `latest`) with two
  implementations. `VITE_DATA_MODE=dummy` uses the sample provider (`dummy.ts`, `dummyCatalog.ts`, generated by
  `ops/template/gen_data.py`), fetched as a separate chunk only in that mode; anything else uses the live provider
  (`live.ts`) over the API. Production builds in the mode of the repository variable `PORTAL_DATA_MODE`
  (unset = sample); sample mode shows "Dane przykładowe" in every page's footer.
- **API** (`apps/portal/functions/api`, `apps/portal/server`): same origin as the portal, so one Access app covers
  both. Metric series over R2 SQL (only metrics and columns in the semantic manifest; filter values validated and
  quoted; cached at the edge for an hour) and the published layer (catalogue, latest values) read over the S3 API
  with a read-only key pair.
- **Semantic** (`packages/semantic`): the manifest the API checks queries against, the published catalogue
  contract, the dashboard format v3 and yardsticks validators.
- **Visuals** (`packages/visuals`): the chart library (`ZChart`), no portal logic. The guide's samples are a
  separate entry (`@zohelo/visuals/samples`) so pages that draw charts do not carry them.
- **Dashboards** (`dashboards/domains/*.yaml`, `dashboards/yardsticks.yaml`): parsed to JSON at build time
  (`apps/portal/vite-yaml.ts`), validated on load and in CI (`ops/check-dashboards.ts`).
- **Access**: a Cloudflare Access app over `bi.zohelo.com`, `zohelo-bi.pages.dev` and every preview subdomain
  (`ops/ensure-platform.ts`); sign-in by one-time PIN to the allowed emails. The deploy fails when a hostname
  answers without sign-in.
- **Credentials**: organisation-level only (see the infrastructure doc). Workflows map them onto the names the
  tools read, in one block.

## Not yet

- Live data for the template: published contract v2 (breakdowns, EU and voivodeship geographies, release
  calendar, aggregation per KPI), then the first real slice (roadmap stage B).
- Accounts: favourites, saved views and collections live in the browser (`localStorage`).
