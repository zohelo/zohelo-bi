## Live provider on contract v2 (2026-11-11, branch `feat/live-v2-provider`)
`data/live.ts` reads zohelo-data's published contract v2 (`06_published/v2`, docs/published.md) through
`/api/published/v2/{catalog,latest,calendar,kpi/<key>/series}` (prefix derived from `PUBLISHED_PREFIX` like the topics
route; validators `validate*V2` in `packages/semantic/src/published.ts`; fixtures copied from zohelo-data in
`packages/semantic/fixtures/v2`). `VITE_DATA_MODE=dummy` stays the production default; switching to live is the owner's call.
- Series: one per geography × source × members (O31). Default source per geography = the preferred source with data
  at the KPI's frequency, preferring the first geography's unit; `sources` picks, `allSources` returns all. A series
  at another frequency (planned in the contract) is never a default and comes back marked `frequency`. The explorer and
  dashboards send a source only when the reader chose one.
- Units: every series and latest value has its own `unit_key`; a KPI is labelled with the unit of Poland's latest value
  (`catalog_unit_key` keeps the catalogue's); charts take their series' unit when they all share one
  (`relabelKpi`); the explorer notes mixed units or frequencies; the indicator page compares sources in their own units.
- Published `polarity` and `aggregation` replace the template's guesses (`rememberPolarity`, `averageLike`).
- Geography keys are the contract's everywhere (`PL-02` … `PL-32`, `EL`, `EU27`); old `PL14` links redirect (`legacy.ts`).
- Topics review: `?tematy=przeglad` (sessionStorage) reads `06_published/v1/review/topics.json` through
  `/api/published/v1/review/topics.json`, in sample mode too, with the banner "Tematy i nagłówki: dane rzeczywiste
  (przegląd wewnętrzny) · wskaźniki: przykładowe". The UI suite serves API fixtures listed in `tests/ui/pages.json` `api`.
