# zohelo-bi

The zohelo BI platform on top of [zohelo-data](https://github.com/zohelo/zohelo-data):
dashboards, a data explorer and the measure catalogue at **bi.zohelo.com** (sign-in required).

Today it reads the Gold proof of concept (namespace `poc`): small real samples of population,
GDP, unemployment, inflation and NBP exchange rates from Eurostat, GUS, World Bank and NBP.

## Layout

| Path | What |
|---|---|
| `packages/semantic` | The semantic manifest: metrics, their tables and dimensions. Later generated by zohelo-data. |
| `packages/visuals` | Chart components (Vega-Lite in React), themed from the page's CSS tokens. Reusable by zohelo.com. |
| `apps/portal` | The portal (React + Vite) and its query API (`functions/api`, Cloudflare Pages Functions over R2 SQL). |
| `dashboards` | Dashboards as YAML: tiles name a metric, a chart type and filters. |
| `ops/` | Cloudflare setup (`ensure-platform.ts`), checks and the smoke test used by the deploy workflow. |

More in [docs/architecture.md](docs/architecture.md).

## Deploying

Pull requests run `.github/workflows/check.yml`: frozen install, type check, dashboard check,
build and a smoke test of every API endpoint and dashboard tile against the real lakehouse (read
token only, nothing deployed). Pushes to `main` run `.github/workflows/deploy.yml`: the same
checks, Cloudflare setup, deploy to bi.zohelo.com and a sign-in check. For a preview, run
`deploy.yml` by hand on a branch (Actions → Deploy portal → Run workflow); it deploys to
`<branch>.zohelo-bi.pages.dev`. All hostnames are behind Cloudflare Access (one-time PIN to the
emails in `PORTAL_SIGNIN_ALLOWED_EMAILS`).
check.yml fails when an action is not pinned to a full SHA.

## Adding a dashboard

Copy `dashboards/overview.yaml`, change `id`, `title` and the tiles. A tile names a
metric id from `packages/semantic`, `chart: line | bar` and filters by dimension column. A bar
tile with `selects: true` sets `$selected` for the other tiles (click a bar to drill in).

## Local development

`bun install`, then `bun run dev` for the portal. The API needs `wrangler pages dev` in
`apps/portal` with a `.dev.vars` file (see `ops/smoke.sh`); without it the pages load but show errors.
